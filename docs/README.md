# 考公平台 (Kaogong Platform) - 终极技术与业务说明书

> **文档状态**: 最终竣工版 (V1.0)
> **系统定位**: 基于大模型 (LLM) 与极速 OCR 视觉能力构建的现代化智能教培基座。

---

## 1. 项目愿景与痛点解决

本平台旨在彻底颠覆传统考公刷题软件（如粉笔、华图）的固定答案模式。通过引入真实 AI 大脑和创新型商业模式，解决以下三大备考痛点：

1. **解析单一且僵化**：传统题库只有一种标准解析。本系统引入**名师流派系统**与**苏格拉底追问系统**，同一道题提供“公式流”、“画图流”等多维度解析，且支持用户向 AI 老师发起无限次针对性追问。
2. **缺乏外部督导与坚持动力**：本系统独创了**对赌契约打卡模型**。用户充值押金发起挑战，完成每日打卡则原路退回并瓜分失败者奖金，利用“厌恶损失”心理实现零人力成本的高效督学。
3. **录题成本极高**：传统教培机构需雇佣大量兼职录题。本系统引入基于 ONNX 的极速 **RapidOCR 引擎**，实现图片拖拽秒级入库，大幅降低教研成本。

## 2. 全局技术架构蓝图 (Architecture)

本系统采用极其现代且具备高扩展性的微服务架构体系，分离关注点，确保各个端独立迭代：

### 2.1 后端中枢引擎 (Backend - NestJS)
- **核心框架**: NestJS + TypeORM
- **数据库**: PostgreSQL (承载高维关系型数据)
- **职责**: 负责核心业务逻辑处理，包括题库流转、JWT 安全鉴权、大模型 Prompt 拼装调度、支付对赌合约流转、热力图能力追踪等。
- **大模型接入**: 深度集成 `@langchain/openai`，通过标准的 OpenAI 接口协议无缝兼容通义千问 (Qwen)、DeepSeek 等高性价比国产大模型。

### 2.2 极速视觉微服务 (OCR Service - FastAPI)
- **核心框架**: Python FastAPI
- **推理引擎**: `rapidocr-onnxruntime`
- **职责**: 作为 Sidecar 微服务部署，专职负责将图片中的中文题目提取为结构化文本。由于采用 CPU 极限优化的 ONNX 模型，无需昂贵的 GPU 算力即可实现百毫秒级响应，且不阻塞 Node.js 的主线程。

### 2.3 C端前台应用 (Frontend - Taro)
- **核心框架**: Taro + React
- **职责**: 微信小程序与 Web 多端同构的刷题主阵地。
- **亮点**: 
  - 引入无焦虑正向计时器。
  - 基于本地磁盘 `setStorageSync` 的单题实时缓存防御阵列，彻底杜绝断网导致进度丢失。
  - 支持多名师切换的解析看板。

### 2.4 B端管理后台 (Admin - React + Vite)
- **核心框架**: React + Vite + Ant Design
- **职责**: 教研与运营大盘。
- **亮点**: 题库大厅支持**多线程并发大模型解析**。录题后，只需点击“一键生成解析”，后台会自动并发调度两名不同流派的 AI 名师进行解析填充。

### 2.5 基础设施与环境 (Infrastructure - NixOS)
- **环境管理**: 全面适配 NixOS。通过 `flake.nix` 声明式管理 Node.js, Python, PostgreSQL, pnpm 等底层依赖，确保开发与生产环境绝对隔离与高度一致。

## 4. 核心系统流转解析

### 4.1 "拍照即入库" 流转 (OCR)
1. 教研员在 Admin B端上传图片。
2. NestJS 后端 `QuestionsController` 接收图片，通过 Node 原生 `fetch` 将二进制 Blob 转发给 `http://localhost:8000/api/ocr`。
3. Python FastAPI 使用 ONNX 模型提取文本，并原路返回。
4. NestJS 将文本存入 PostgreSQL。

### 4.2 "多流派解析并发" 流转 (Batch AI)
1. 教研员在 B端点击“一键生成解析”。
2. NestJS 随机挑选 2 名已注册的名师（如：老王、王老师）。
3. 使用 `Promise.all` 开启多线程，同时向 Qwen/DeepSeek 发送请求，Prompt 结构为：`你扮演[名师设定]，请用你的流派解答：[题干]`。
4. 结果合并后返回给前台展示。

### 4.3 "对赌督学" 商业流转 (Pledge Contract)
1. C端用户发起 30 天打卡挑战，发起支付请求。
2. `PaymentsService` 生成状态为 `PENDING` 的 `PledgeContract` 实体，模拟生成微信支付预下单参数。
3. 支付成功后（通过 `/webhook/wechat` 回调），合约状态变更为 `ACTIVE`。
4. 后续每次 `StatsService` 记录用户答题完成时，核查打卡逻辑。

## 5. 本地运行与部署指南

长官，系统采用微服务隔离设计，在本地调试时需**分别启动四大模块**。
得益于 Nix 环境，无需担心依赖污染。请确保 PostgreSQL 已在 5432 端口启动（用户名：`kaogong_user`，密码：`kaogong_password`，数据库：`kaogong_db`）。

**步骤 1：启动 Python OCR 视觉中心**
```bash
cd ocr-service
# (首次需 pip install -r requirements.txt)
uvicorn main:app --reload --port 8000
```

**步骤 2：启动 NestJS 核心大脑**
```bash
cd backend
# 配置大模型秘钥
export OPENAI_API_KEY="sk-your-llm-key" 
export OPENAI_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
pnpm install
pnpm run start:dev
# 后端将监听 3000 端口
```

**步骤 3：启动 B端教研大盘**
```bash
cd admin
pnpm install
pnpm run dev
# B端将监听 5173 端口
```

**步骤 4：启动 C端刷题平台**
```bash
cd frontend
pnpm install
pnpm run dev:h5
# C端 Web 版将监听 10086 (或其他 Taro 默认端口)
# 如果调试小程序，运行 pnpm run dev:weapp，并在微信开发者工具导入项目
```
